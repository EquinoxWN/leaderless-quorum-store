## Three-process demo

Command: `bash scripts/demo.sh` (builds the binary, starts three `serve` processes on
127.0.0.1:7101-7103, stops them one by one). Output in `docs/proof/demo.jpg`:

| Step | Setting | Result |
|---|---|---|
| all 3 up | R=2 W=2 | put ok (tag 1@cli), get returns "alice" |
| node a stopped | R=2 W=2 | put ok (tag 2@cli), get returns "bob" from 2 replies |
| nodes a and b stopped | R=2 W=2 | put fails: version query needs 2 of 3 replicas, got 1 |
| nodes a and b stopped | R=1 W=1 | put ok (tag 3@cli), get returns "dave" from 1 reply |

Each CLI call is a separate process with a fresh logical clock, and the tags still increase,
because the version comes from the replicas (ADR 0002).

### Reading the numbers (Analyze)

- Every R + W > N setting returned 0 stale reads in 2,000 trials, at N=3 and N=5 (21 settings in
  total), as the overlap argument predicts.
- Every R + W <= N setting returned stale reads, and the measured rate is within 0.021 of
  C(N-W, R) / C(N, R) in every row.
- Fault tolerance follows N - max(R, W) for writes and N - R for reads. The cost of overlap shows
  directly: at N=5, R=3 W=3 survives 2 nodes down for both operations, while R=1 W=5 tolerates 4
  down for reads and none for writes.
- Writes depend on R as well as W because the version query uses the read quorum (ADR 0002). For
  example N=3, R=2, W=1 tolerates only 1 node down for writes.

### Control

- `scripts/overlap_gate.sh` fails the build if any R + W > N row shows a stale read (checked by
  feeding it an edited table with one stale row and an empty table: both exit 1).
- `.tmp/check.sh` (local) and `make ci` (CI) run lint, tests and the gate.

## Vulnerability audit

`bash scripts/vulncheck.sh` (govulncheck v1.8.0, Go 1.26.10): one finding, **GO-2026-6859**
(net/http server crash due to a MaxBytesReader header race), in the Go standard library, fixed in
Go 1.26.11. The portfolio pins Go 1.26.10, so the script allows exactly this ID with a `::warning`
and fails on anything else. The same scan with Go 1.26.11 printed "No vulnerabilities found."
Moving the pin to 1.26.11 removes the exception.
