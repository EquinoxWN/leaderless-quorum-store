# Quality check, 2026-11-01 rules (applied 2026-11-12)

The owner's 10 rules, applied while M1 was built, on Windows 11 with Go 1.26.10. The race detector
needs cgo, which this machine lacks; CI runs `make test` with `-race`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | Every replica call runs under a per-phase context timeout (`quorum.fanout`, `context.WithTimeout`) and is retried at most `Retries` times (0..5) with doubling backoff capped at 1 s (`quorum.call`); permanent errors (`ErrRejected`, `ErrUnknownNode`) are not retried (`TestRetriesAreBoundedAndSkipPermanentErrors`). The HTTP client has `http.Client.Timeout`; the server has read-header, read, write and idle timeouts and a 5 s shutdown limit (`cmd/.../main.go` `serve`). A failed quorum returns `*quorum.Error` with every replica error (`errors.Join`), tested with `errors.Is(err, transport.ErrUnreachable)`. Ignored results are only response-body drain/close and writes to a client that has gone, each commented (`internal/transport/http.go`). |
| 2 | Writes safe to retry | pass | A replica stores a record only if its tag is newer (`replica.Apply`), so a repeated or late write is a no-op: `TestApplyKeepsNewestAndIsIdempotent` applies the same write twice and asserts one effect. Retries of a write re-send the same tag. No files are written. |
| 3 | No race conditions | pass | Replica map under `sync.RWMutex`; coordinator logical clock under a mutex (`next`, `observe`); fault maps in `transport.Local` under a mutex; background calls tracked by a `WaitGroup` and results sent to a buffered channel so no goroutine blocks after the caller returns. Concurrent tests: `TestConcurrentClientsConverge` (3 coordinators, 600 operations), `TestConcurrentAppliesConvergeOnHighestTag` (8 writers). `-race` in CI only. |
| 4 | Don't trust the clock | pass | Versions come from replica tags and a logical clock, never from wall time (ADR 0002). Durations use `context.WithTimeout`/`time.NewTimer` (monotonic). No timestamps are stored. Tests measure elapsed time with `time.Since` on `time.Now` (monotonic in Go). |
| 5 | Read before changing | pass | No environment variables or config files are read; every CLI flag is listed in `usage` and the README. Paths in the README exist (checked by `audit_repo.py`). |
| 6 | Never break compatibility | pass | First release. The wire format is JSON with optional `value` and `deleted` fields; the server rejects unknown fields, so a future field must be added to the server before clients send it (noted for M2). |
| 7 | One source of truth | pass | Each replica's map is the only copy of its data; there are no caches. Go version: CI and README say 1.26.10; `go.mod` states the minimum language version (1.23). The ring is rebuilt from the `-nodes` flag on each CLI call. |
| 8 | Small changes, no secrets, validate input | pass | Standard library only, no secrets. Validation: keys 1..256 bytes of UTF-8, values up to 1 MiB, writer ids 1..64 bytes, tag counter > 0, tombstones without a value (`replica.Validate`); N 1..16, 1 <= R, W <= N, positive timeout (`Config.Validate`); node URLs must be `http(s)://host:port`; request bodies capped with `MaxBytesReader`, unknown JSON fields rejected, body key must match the path; CLI argument counts and flags checked (17 bad argument sets in `TestRunRejectsBadArguments`). |
| 9 | Tests that can actually fail | pass | No skips or tautologies (`grep -rn "t.Skip\|assert True" .` finds none). Empty, invalid and failure paths covered for each entry point (tables above in `docs/results/m1.md`). Mutation check below: 14 of 17 killed before, 2 tests and 1 test case added, 17 of 17 after. The CI overlap gate was shown to fail on a table with one stale row and on an empty table. |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: gofmt clean, `go vet` clean, 44 tests passed, overlap gate 0 stale reads in 6 R+W>N settings, govulncheck only GO-2026-6859 (see below), `CHECK PASS`, run twice. `python .tools/audit_repo.py leaderless-quorum-store`: OK. CI not run yet (not pushed). |

Known limitation (rule 1/10): govulncheck v1.8.0 with Go 1.26.10 reports GO-2026-6859 (net/http,
standard library), fixed in Go 1.26.11. The portfolio pin is 1.26.10, so `scripts/vulncheck.sh`
allows exactly that ID with a `::warning` and fails on any other. With Go 1.26.11 the scan reports
no vulnerabilities. The exception goes when the pin moves.
